2.2Scaled dot-product attention

The one operation the whole Transformer is built from – Section 3.2.1 and Figure 2 (left) of Vaswani et al. (2017). Where it sits in the model: topic 2.1.

The gist in 60 seconds

  1. Every position produces a query (what am I looking for?), a key (what do I offer?) and a value (what do I pass on?).
  2. Score = dot product of a query with every key. High score = good match.
  3. Divide by √dk, then softmax → non-negative weights that sum to 1.
  4. Output = weighted sum of the values: a soft lookup instead of picking one entry.
  5. All queries at once: Attention(Q,K,V)=softmax(QKTdk)V

2.2.1Query, key, value

The paper describes attention as “mapping a query and a set of key-value pairs to an output” (Section 3.2). The database analogy helps:

AnalogyIn the model
Query qThe search requestWhat this position wants to know about the rest of the sequence
Key kThe label on a drawerWhat the position at the other end advertises about itself
Value vThe content of the drawerThe information that is actually handed over if the match is good

Unlike a database lookup, nothing is selected hard. Every value contributes, weighted by how well its key matches the query – therefore soft lookup.

Where do Q, K, V come from? From learned linear projections of the layer input (details in 2.3). In self-attention all three come from the same sequence; in the decoder's encoder–decoder attention the queries come from the decoder and the keys and values from the encoder output (see 2.1.4).

2.2.2The formula

Attention(Q,K,V)=softmax(QKTdk)V Equation (1) of the paper. Queries and keys have dimension dk, values dv.

Reading it as shapes makes it concrete – n queries, m key-value pairs:

StepShapeWhat happens
Q, K, Vn×dk, m×dk, m×dvOne row per position.
QKTn×mScore matrix: row i, column j = how well query i matches key j.
÷ √dkn×mRescaling, see 2.2.4.
softmaxn×mRow-wise, i.e. over the keys: every row is non-negative and sums to 1.
· Vn×dvEach row becomes a weighted sum of the value rows – one output vector per query.

Worked example by hand (dk = dv = 2, one query)

Query q = (2, 1), three key-value pairs:

jkjvjq·kj÷ √2softmax
1(1, 0)(1, 0)21.410.25
2(0, 2)(0, 1)21.410.25
3(1, 1)(1, 1)32.120.50

Output = 0.25·(1,0) + 0.25·(0,1) + 0.50·(1,1) = (0.75, 0.75). The third pair matches best, so its value dominates – but the others still contribute.

2.2.3Dot product as compatibility, softmax as weighting

The dot product q·k=∑iqiki is large when the two vectors point in a similar direction: it is the compatibility measure. The softmax then turns the raw scores into weights:

αj=esj∑lesl,output=∑jαjvj All αj > 0 and Σαj = 1 – the output is a convex combination of the values.

Two properties matter in practice:

  • Only differences between scores count – adding a constant to all scores changes nothing.
  • The whole thing is one matrix multiplication for all queries at once: fast and memory-efficient on GPUs, which is exactly why this variant is used (2.2.6).

2.2.4Why divide by √dk

Assume the components of q and k are independent with mean 0 and variance 1. Then

q·k=∑i=1dkqiki,mean=0,variance=dk Footnote 4 of the paper. Typical magnitude of a score therefore grows like √dk – with dk = 64 that is already ±8.

Large scores push the softmax into a saturated region: one weight goes to ≈ 1, all others to ≈ 0, and its gradients become extremely small – the layer barely learns. Dividing by √dk brings the variance back to ≈ 1, regardless of head size.

Common trap: the division is not what makes the weights sum to 1 – the softmax does that on its own. And it is not a normalisation of the vectors either. It is purely about keeping the variance of the scores at ≈ 1 so the softmax keeps usable gradients.

2.2.5Masking inside the attention

Sometimes a query must not see certain positions: future tokens in the decoder (2.1.4) or padding in a batch. The trick sits between scaling and softmax: the forbidden scores are set to −∞. Since e−∞=0, those weights become exactly 0 and the remaining weights still sum to 1.

2.2.6Dot-product vs additive attention

Additive (Bahdanau, 1.2)Dot-product (here)
CompatibilitySmall feed-forward net with one hidden layerPlain dot product q·k
Theoretical complexitySimilarSimilar
In practiceSlower, more memoryMuch faster: one optimised matrix multiplication
Small dkOn parOn par
Large dkBetter than unscaled dot-product attentionNeeds the 1/√dk scaling to keep up

So the “scaled” in the name is exactly the fix that makes the fast variant work at the head sizes the Transformer uses.
